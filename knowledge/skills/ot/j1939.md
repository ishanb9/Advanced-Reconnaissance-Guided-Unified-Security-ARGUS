# SAE J1939 (heavy vehicle) guidance

SAE J1939 is the dominant in-vehicle networking standard for heavy-duty trucks, buses, agricultural
machinery, and construction equipment. It runs over a two-wire CAN bus (ISO 11898) at 250 kbit/s and
encodes data using **Parameter Group Numbers (PGNs)** — logical message identifiers — each carrying
one or more **Suspect Parameter Numbers (SPNs)** that map to named signals such as engine RPM, vehicle
speed, brake pressure, and transmission gear. Because J1939 was designed for closed, trusted networks
it provides **no authentication, no encryption, and no message integrity** by default. Any node that
can physically reach the bus — via the OBD-II/J1939 diagnostic connector under the dashboard, a
telematics unit splice, or a compromised ECU — can read all traffic and broadcast arbitrary commands.

**ARGUS surfaces this technology as guidance only. Auto-execution is not possible because
J1939 requires a physical CAN bus connection through dedicated hardware.** Supported adapters
include SocketCAN-compatible USB-CAN bridges (PEAK PCAN-USB, Kvaser Leaf, Intrepid RAD-Galaxy,
VSCOM USB-CAN), the Flipper Zero with the CAN Bus module, or custom OBD-II J1939 adapters. The
operator must establish a wired tap on the vehicle's J1939 backbone or use the 9-pin or 16-pin
diagnostic port before any tool can communicate. Where a telematics gateway (e.g. Geotab, CalAmp,
Omnitracs) bridges J1939 data to an IP back-end, ARGUS may correlate observed telematics IP traffic
— unusual PGN injection signatures, replay storms, or address-claim floods — with OT anomalies, but
the root-cause hardware investigation always requires physical access.

**Safe-first approach.** Begin with fully passive capture using `candump` or `cansniffer` on a
SocketCAN interface; these tools only listen and do not transmit frames. Use TruckDevil's
`--listen` mode or J1939-Python's `subscribe()` API to decode PGNs and SPNs without sending a
single bit. Correlate decoded SPNs against the SAE J1939-71 data dictionary to identify safety-
critical signals (PGN 0xF001 / Electronic Brake Controller 1, PGN 0xFEF1 / Cruise Control, PGN
0xFEF7 / Vehicle Speed). **Never transmit on a live J1939 bus — including replay attacks, address-
claim spoofing, or PGN injection — without explicit written authorization, a vehicle in a controlled
static environment, and a human operator ready to cut ignition.** A spoofed brake or throttle PGN
on a moving vehicle is an immediate life-safety event.

**Key risks and remediation.** Documented attacks include address-claim spoofing to silence legitimate
ECUs, PGN injection to command throttle or disable brakes, and firmware extraction via J1939 transport-
protocol (TP) commands directed at the engine ECU. Telematics units that expose a cellular or Wi-Fi
IP interface while also bridging J1939 create a remote-to-bus attack path (CVE-2021-3989 class). To
remediate: physically secure the diagnostic port (lockout cover, monitoring relay); deploy a J1939
intrusion detection system (e.g., Upstream Security, Karamba) to detect anomalous PGNs or address
floods; isolate telematics gateways from the primary J1939 backbone via a unidirectional data diode
where feasible; apply firmware signing to ECUs; and follow NIST SP 800-82 Rev 3 and SAE J3101
hardware security recommendations for new deployments.
