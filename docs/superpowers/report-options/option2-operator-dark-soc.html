Engagement Outcome

ARGUS chained a server-side request forgery into an internal admin panel, bypassed an upload filter to plant a webshell (unauthenticated RCE → www-data foothold), then abused a sudo NOPASSWD on /usr/bin/git (GTFOBins) to escalate to root — end to end, autonomous. user.txt + root.txt captured.

Attack chain: SSRF (T1190) → Upload bypass / Webshell (T1505.003) → RCE (T1059) → Sudo git privesc (T1548.003) → Root → Credential loot (T1003)

Priority Actions

  • 1
    Immediately implement an egress allow-list on the internal fetch service to kill the SSRF root cause. Until patched, the internal admin panel is reachable from the web tier without authentication.
  • 2
    Enforce upload validation using MIME-type + magic-byte inspection and store all uploads off the web root on a noexec mount. The double-extension bypass was trivial and gave direct RCE.
  • 3
    Remove sudo NOPASSWD: /usr/bin/git immediately. Any www-data process (or lower-privilege attacker foothold) can use GTFOBins to reach root in seconds.
  • 4
    Rotate all leaked credentials: /root/.ssh/id_rsa (revoke + regenerate), DB credentials from config.php, and any secrets readable under the www-data or root context.
  • 5
    Patch Apache 2.4.41, enable CSP + HSTS + X-Frame-Options headers, disable the TRACE method, and HTML-encode the /search output to close the reflected XSS. Disable TLS 1.0/1.1.

§4 Attack Path

Attack Path & Kill Chain

Full autonomous exploit chain from external attacker to root, confirmed on retest. Each node is colour-coded by MITRE tactic.

Kill Chain Narrative
STAGE 1 — T1190 SSRF

Probed /api/fetch?url= with an internal loopback URL. No allow-list; the service faithfully fetched http://127.0.0.1:8080 and returned the internal admin HTML.

STAGE 2 — T1505.003 Upload Bypass

The internal admin panel exposed /upload. A double-extension file (shell.php.jpg) with a PHP magic-byte header bypassed the content filter; the webshell was written to /uploads/.

STAGE 3 — T1059 Webshell RCE

HTTP request to the uploaded shell with cmd=id returned uid=33(www-data). Interactive shell established. LinPEAS surfaced the sudo misconfiguration.

STAGE 4 — T1548.003 Sudo GTFOBins

sudo -l revealed NOPASSWD: /usr/bin/git. Invoked sudo git -p help config then !/bin/sh to break out to a root shell.

STAGE 5 — T1003 Credential Access

As root: read /root/root.txt, exfiltrated /root/.ssh/id_rsa, and retrieved DB credentials from /var/www/app/config.php.

§7 Detailed Findings

Detailed Finding Cards

F-01 Critical Server-Side Request Forgery (SSRF) to Internal Admin Panel CVSS 9.1 Verified
Description
The /api/fetch endpoint accepts an arbitrary URL parameter and performs a server-side HTTP request without any allow-list validation. An unauthenticated attacker can supply url=http://127.0.0.1:8080 to reach the Werkzeug-based internal admin panel, which is not exposed to the internet directly.
Impact
Full access to the internal admin panel, including the file-upload endpoint used in the next attack stage. This was the critical pivot that enabled the full compromise chain. An allow-listed fetch service would have prevented stages 2 through 6 of the kill chain.
MITRE ATT&CK
T1190 — Exploit Public-Facing Application
Host / Port
FORGE (10.129.21.254) :80
Evidence — HTTP Request
GET /api/fetch?url=http://127.0.0.1:8080/admin HTTP/1.1 Host: 10.129.21.254 HTTP/1.1 200 OK Content-Type: text/html <!-- FORGE Internal Admin Panel --> <h1>Admin Dashboard</h1> <a href="/upload">Upload Files</a>
SHA-256:a1b2c3d4e5f67890aabb1122334455667788990011aabb2233445566778899aa
Remediation
Implement a strict egress allow-list for the fetch service (whitelist specific external domains only). Block all requests to RFC-1918 / loopback addresses at the application layer. Consider disabling the fetch endpoint entirely if not required. Deploy a WAF rule for SSRF patterns as a defence-in-depth measure.
F-02 Critical Unauthenticated File Upload → Remote Code Execution (Webshell) CVSS 9.8 Verified
Description
The internal admin /upload endpoint (reachable via the SSRF — F-01) does not enforce file-type validation. A PHP webshell with a double extension (shell.php.jpg) and a PHP magic-byte header bypassed the server-side content filter and was written to the web-accessible /uploads/ directory.
Impact
Unauthenticated Remote Code Execution as www-data. An attacker gains an interactive shell on the host, enabling enumeration, lateral movement, and privilege escalation. The webshell persists across restarts until removed.
MITRE ATT&CK
T1505.003 — Web Shell   T1059 — Command & Scripting Interpreter
Host / Port
FORGE (10.129.21.254) :80 via SSRF :8080
Evidence — RCE Proof
POST /upload HTTP/1.1 Host: 127.0.0.1:8080 (via SSRF) Content-Type: multipart/form-data -- filename="shell.php.jpg" -- <?php system($_GET['cmd']); ?> # RCE confirmation: GET /uploads/shell.php.jpg?cmd=id HTTP/1.1 HTTP/1.1 200 OK uid=33(www-data) gid=33(www-data) groups=33(www-data)
SHA-256:a1b2c3d4e5f6789012345678901234567890abcdef1234567890abcdef123445
Remediation
Enforce upload validation using MIME-type inspection AND magic-byte verification. Reject double extensions. Store all uploads outside the web root on a noexec-mounted volume. Rename uploaded files to UUIDs with no extension. Add server-side PHP execution block for the uploads directory via Apache config (php_flag engine off).
F-03 High Sudo Misconfiguration: NOPASSWD /usr/bin/git → Root (GTFOBins) CVSS 8.8 Verified
Description
The /etc/sudoers file grants www-data the ability to run /usr/bin/git as root without a password. The GTFOBins technique for git exploits the pager (sudo git -p help config) to spawn an interactive shell via !/bin/sh.
Impact
Full root privilege escalation from a www-data foothold in under 30 seconds. Attacker obtains root shell; can read any file, install backdoors, pivot to other systems using the leaked SSH key, or fully compromise the host.
MITRE ATT&CK

F-04 High Outdated Apache HTTP Server 2.4.41 (Multiple CVEs) 7.5 Open
Description
Apache 2.4.41 was released in August 2019. The current stable release at time of assessment is 2.4.62. Multiple CVEs affecting 2.4.41 through 2.4.57 include path traversal (CVE-2021-41773, applicable to 2.4.49), mod_lua buffer overflow, and request-smuggling vulnerabilities. No publicly available RCE was confirmed exploitable against this specific configuration; the finding is flagged for patching priority.
Evidence
Server: Apache/2.4.41 (Ubuntu) X-Powered-By: PHP/7.4.3 # nikto output: + Apache/2.4.41 appears to be outdated (current: 2.4.62) + OSVDB-877: HTTP TRACE method is active
Remediation
Upgrade Apache to 2.4.62 or latest stable release via apt-get upgrade apache2. Enable automatic security updates for OS packages. Suppress the Server version banner (ServerTokens Prod, ServerSignature Off). Disable TRACE: TraceEnable Off.
F-05 Medium Reflected Cross-Site Scripting (XSS) on /search CVSS 6.1 Verified
Description
The q parameter of the search endpoint is reflected in the HTML response without HTML entity encoding. An attacker can inject a script payload into the URL, which executes in the victim's browser when they click a crafted link.
Impact
Session cookie theft, credential phishing overlays, client-side redirection, and defacement. Exploitability requires social engineering to deliver the payload URL to a victim.
MITRE ATT&CK
T1059.007 — JavaScript
Evidence
GET /search?q=<script>alert(document.cookie)</script> HTTP/1.1 HTTP/1.1 200 OK <div class="results"> Results for: <script>alert(document.cookie)</script> <!-- Script reflected unencoded; executes in browser -->
Remediation
HTML-encode all user-supplied input before rendering it in the response. Use a templating engine with auto-escape enabled. Add a Content Security Policy header (Content-Security-Policy: default-src 'self') as a defence-in-depth measure.
F-06 Medium Missing Security Headers (CSP / HSTS / X-Frame-Options) CVSS 5.3 Open
Description
HTTP responses from FORGE:80 are missing Content-Security-Policy, Strict-Transport-Security, and X-Frame-Options headers. This increases the risk of XSS, clickjacking, and protocol downgrade attacks.
Remediation
Add to Apache virtual host: Header always set Strict-Transport-Security "max-age=63072000; includeSubDomains", Content-Security-Policy, and X-Frame-Options DENY.
F-07 Medium HTTP TRACE Method Enabled CVSS 4.8 Open
Description
The HTTP TRACE method is enabled on FORGE:80. TRACE can be abused in Cross-Site Tracing (XST) attacks to exfiltrate session cookies that are flagged HttpOnly, by leveraging a cross-domain XSS vector to make a TRACE request.
Remediation
Add TraceEnable Off to Apache configuration. Verify with curl -X TRACE http://target/ post-remediation.
F-08 Low TLS 1.0 / 1.1 Enabled CVSS 3.7 Open
Description
TLS 1.0 and TLS 1.1 are deprecated protocols with known cryptographic weaknesses (POODLE, BEAST). Both are disabled by major browser vendors but remain enabled on FORGE, widening the attack surface for network-adjacent attackers.
Remediation
In Apache SSL config: SSLProtocol all -SSLv3 -TLSv1 -TLSv1.1. Enable only TLS 1.2 and TLS 1.3. Verify with testssl.sh post-remediation.
F-09 Low Verbose Server / Version Banners Disclosed CVSS 3.1 Open
Description
HTTP response headers disclose Apache version (Apache/2.4.41), PHP version (PHP/7.4.3), and Python/Werkzeug version. This information aids targeted exploitation and reduces attacker effort in fingerprinting the stack.
Remediation
Set ServerTokens Prod and ServerSignature Off in Apache config. Set expose_php = Off in php.ini. Suppress Werkzeug server headers in production (use a proper WSGI server, not dev server).
§8 Coverage

Tested — Not Exploitable

These attack paths were tested exhaustively and did not yield exploitation. They are documented here so the client has a complete picture of coverage, not just confirmed hits.

SQL Injection on /api?id=
Tested: 5 SQLi techniques, ~1,200 requests via sqlmap (union, boolean, error, time, stacked). Result: parameter is integer-cast server-side before any SQL interpolation. Not injectable under any tested vector.
SSH Root Brute Force
Tested: hydra with top-1000 password list against root@10.129.21.254:22. Result: SSH rate-limiting active (connection throttled after 3 attempts). Root account configured for key-only authentication; password auth rejected at protocol level.
Default Credential Spray on /login
Tested: 47 default credential pairs (admin/admin, admin/password, root/root, forge/forge, etc.). Result: all rejected with 403 / generic error. No lockout policy triggered, but no default credentials accepted.
CSRF on State-Changing Forms
Tested: all POST forms on :80 for missing or bypassable CSRF tokens. Result: anti-CSRF tokens are present on all state-changing forms and are validated server-side. Token rotation occurs per request. Not exploitable.

§13 Remediation

Remediation Roadmap

P1 — NOW (0–7 days)
  • Implement strict egress allow-list on /api/fetch; block all RFC-1918 + loopback targets
  • Enforce upload validation: MIME type + magic-byte inspection; reject double extensions
  • Move uploads off web root to noexec mount; block PHP execution in uploads dir
  • Remove NOPASSWD: /usr/bin/git from sudoers immediately
  • Rotate /root/.ssh/id_rsa (revoke & regenerate key pair)
  • Rotate DB credentials in config.php; rotate APP_SECRET
  • Remove / quarantine the deployed webshell from /uploads/
P2 — SHORT TERM (7–30 days)
  • Patch Apache to 2.4.62 or latest stable release
  • Add CSP, HSTS, X-Frame-Options, X-Content-Type-Options headers
  • Disable HTTP TRACE method (TraceEnable Off)
  • HTML-encode user input on /search output (fix reflected XSS)
  • Audit all sudo rules against GTFOBins list; apply least-privilege
  • Deploy FIM on web root directories
  • Configure auditd rules for sudo invocation by www-data
P3 — MEDIUM TERM (30–90 days)
  • Disable TLS 1.0 and TLS 1.1; enforce TLS 1.2 / 1.3 only
  • Suppress verbose server/version banners (ServerTokens Prod)
  • Onboard EDR with process-tree visibility for web server process
  • Replace Werkzeug dev server with production WSGI (gunicorn/uWSGI)
  • Implement security-headers.io grade A configuration
  • Purple-team exercise to validate detection coverage post-fix
  • Schedule quarterly penetration testing cadence
